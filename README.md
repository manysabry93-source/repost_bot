# ربات ریپست محتوا (repost-bot)

این ربات هر ۲ دقیقه یک‌بار کانال‌های عمومی مبدا رو چک می‌کنه، از هر پست جدید لینک و آیدی/یوزرنیم رو پاک می‌کنه، امضای تعیین‌شده رو زیرش اضافه می‌کنه و توی کانال‌(های) مقصد خودت منتشر می‌کنه.

## محدودیت مهم
کانال مبدا باید **عمومی** باشه و **یوزرنیم** داشته باشه (مثل `@channelname`). خوندن محتوا از طریق صفحه‌ی پیش‌نمایش عمومی `t.me/s/...` انجام می‌شه، پس نیازی به عضویت ربات توی کانال مبدا نیست.
برای **ویدیو**‌ها: صفحه‌ی پیش‌نمایش عمومی معمولاً فایل ویدیو رو مستقیم نمی‌ده، پس ربات فقط متن پست رو (با پیام هشدار کوتاه) می‌فرسته، نه خود ویدیو رو. برای عکس‌ها کامل کار می‌کنه.

کانال(های) مقصد باید متعلق به خودت باشه و **ربات باید ادمین اونجا** باشه (با اجازه‌ی ارسال پیام) چون ربات باید توش پست بذاره.

## مرحله ۱ — ساخت ربات در تلگرام
۱. توی تلگرام به [@BotFather](https://t.me/BotFather) پیام بده و با `/newbot` یه ربات جدید بساز.
۲. توکنی که می‌ده رو نگه دار (چیزی شبیه `123456:ABC-DEF...`).
۳. آیدی عددی خودت رو از [@userinfobot](https://t.me/userinfobot) بگیر.

## مرحله ۲ — ساخت مخزن روی GitHub
۱. یه ریپازیتوری جدید بساز و همه‌ی فایل‌های این پروژه رو داخلش آپلود کن (از طریق وب‌سایت GitHub، دکمه‌ی "Add file → Upload files").

## مرحله ۳ — گرفتن اطلاعات Cloudflare
۱. وارد داشبورد [Cloudflare](https://dash.cloudflare.com) شو.
۲. از قسمت **Workers & Pages**، یه **API Token** بساز (با دسترسی Edit Workers) — از منوی My Profile → API Tokens → Create Token → قالب "Edit Cloudflare Workers".
۳. **Account ID** رو از همون صفحه‌ی Workers & Pages کپی کن (سمت راست صفحه دیده می‌شه).
۴. یه KV Namespace بساز: در داشبورد Cloudflare برو به Workers & Pages → KV → Create a namespace، اسمش رو مثلاً `BOT_KV` بذار و **ID** ای که می‌ده رو کپی کن.
۵. فایل `wrangler.toml` رو ویرایش کن و مقدار `REPLACE_WITH_YOUR_KV_NAMESPACE_ID` رو با همون ID جایگزین کن (می‌تونی مستقیم توی GitHub ویرایش کنی، نیازی به کامپیوتر نیست).

## مرحله ۴ — تنظیم Secrets در GitHub
داخل ریپازیتوری برو به Settings → Secrets and variables → Actions → New repository secret و این‌ها رو اضافه کن:

| نام Secret | مقدار |
|---|---|
| `CLOUDFLARE_API_TOKEN` | توکنی که در مرحله قبل ساختی |
| `CLOUDFLARE_ACCOUNT_ID` | آیدی اکانت Cloudflare |
| `BOT_TOKEN` | توکن ربات از BotFather |
| `ADMIN_IDS` | آیدی عددی خودت (اگه چند نفر ادمین هستن با کاما جدا کن، مثل `111,222`) |
| `WEBHOOK_SECRET` | یه رشته‌ی تصادفی و دلخواه، مثلاً `x7k29fjq` (فقط برای امنیت آدرس وبهوک) |

## مرحله ۵ — دیپلوی
بعد از اضافه کردن Secrets، به تب **Actions** برو، روی workflow با اسم "Deploy repost-bot to Cloudflare Workers" بزن و "Run workflow" رو انتخاب کن (یا صرفاً یه تغییر کوچیک توی فایلی commit کن تا خودکار اجرا بشه).

بعد از موفقیت دیپلوی، آدرس ربات رو از خروجی Actions یا از داشبورد Cloudflare (چیزی شبیه `https://repost-bot.YOUR-SUBDOMAIN.workers.dev`) پیدا کن.

## مرحله ۶ — فعال‌سازی وبهوک
توی مرورگر برو به:
```
https://repost-bot.YOUR-SUBDOMAIN.workers.dev/setup
```
اگه پیام `"ok":true` دیدی، وبهوک درست تنظیم شده.

## مرحله ۷ — استفاده
۱. توی تلگرام به ربات خودت `/start` بزن.
۲. از منو، کانال‌های مبدا (عمومی) و کانال مقصد (کانال خودت، که ربات توش ادمینه) رو اضافه کن.
۳. امضا از قبل با متنی که خواستی تنظیم شده؛ اگه خواستی تغییرش بدی از دکمه‌ی "ویرایش امضا" استفاده کن.
۴. از این به بعد ربات هر ۲ دقیقه چک می‌کنه و پست‌های جدید رو (بدون لینک/آیدی، با امضای زیرش) توی کانال مقصد منتشر می‌کنه.

### نکات اضافه
- **حالت آزمایشی**: قبل از اینکه واقعاً روی کانال اصلی فعال کنی، می‌تونی حالت آزمایشی رو روشن کنی تا پست‌ها به‌جای کانال مقصد، برای خودت توی چت خصوصی با ربات فرستاده بشه.
- **توقف/شروع**: هر وقت خواستی می‌تونی کل عملیات رو موقتاً متوقف کنی.
- **کلمات فیلتر**: از منو، «افزودن کلمه فیلتر» رو بزن و کلمه یا عبارت‌هایی که می‌خوای بفرست (هر خط یکی). اگه متن یا کپشن یه پست شامل هر کدوم از این کلمه‌ها باشه، اون پست اصلاً منتشر نمی‌شه (نه توی تلگرام، نه توی روبیکا). حذف کلمه‌ها هم از «لیست / حذف کلمات فیلتر» انجام می‌شه.
- **آمار**: تعداد پست‌های منتشرشده و آخرین زمان بررسی رو نشون می‌ده.
- برای جلوگیری از محدودیت‌های رایگان Cloudflare (Subrequests)، بهتره مجموع کانال‌های مبدا و مقصد رو زیر ۲۰ تا نگه داری.

## اتصال به روبیکا (اختیاری)
اگه بخوای همون محتوا رو در یک کانال روبیکا هم منتشر کنه:

۱. توی روبیکا به بخش ساخت بات ("بات‌فادر" روبیکا) برو و یک بات جدید بساز، توکنش رو نگه دار.
۲. توی GitHub Secrets یه مورد جدید اضافه کن: `RUBIKA_TOKEN` با مقدار همون توکن.
۳. دوباره workflow دیپلوی رو اجرا کن (چون سکرت جدید اضافه شده، باید یک‌بار دیگه دیپلوی بشه).
۴. بعد از دیپلوی، به آدرس زیر برو تا وبهوک روبیکا هم ثبت بشه:
```
https://repost-bot.YOUR-SUBDOMAIN.workers.dev/rubika-setup
```
۵. بات روبیکا رو ادمین همون کانال روبیکایی کن که می‌خوای محتوا توش منتشر بشه (مقصد) — و اگه می‌خوای از یه کانال روبیکای دیگه هم محتوا بگیره (مبدا)، ربات باید اونجا هم ادمین باشه (برخلاف تلگرام، برای روبیکا راه دورزدن این محدودیت نداریم — چون صفحه‌ی پیش‌نمایش عمومی مثل `t.me/s/` در روبیکا وجود نداره و فقط با عضویت/ادمین‌بودن پیام‌ها می‌رسه).
۶. توی منوی تلگرام ربات (که با `/start` باز می‌شه)، حالا گزینه‌های مربوط به روبیکا هم دیده می‌شن — هم برای «مبدا روبیکا» (کانالی که ازش محتوا برداشته می‌شه) و هم «مقصد روبیکا». اگه GUID کانال رو نداری، از گزینه‌ی «چت‌های روبیکا شناسایی‌شده» استفاده کن — به‌محض اینکه هر رویدادی از اون کانال به ربات برسه (مثلاً یه پیام امتحانی)، GUID اونجا لیست می‌شه و می‌تونی با یک لمس، هم به‌عنوان مبدا و هم مقصد اضافه‌اش کنی.

کانال‌های مبدای روبیکا برخلاف تلگرام از طریق polling چک نمی‌شن؛ چون پیام‌هاشون همون لحظه از طریق وبهوک به ربات می‌رسه (سریع‌تر از هر ۲ دقیقه حتی).

**صادقانه بگم:** بخش اتصال به روبیکا رو بر پایه‌ی مستندات عمومی و کدهای متن‌باز موجود پیاده کردم، اما چون امکان دسترسی مستقیم به صفحه‌ی رسمی مستندات (rubika.ir/botapi) رو نداشتم، چند جای این بخش ممکنه نیاز به تنظیم دستی داشته باشه:
- ارسال **عکس** به روبیکا (فرآیند آپلود سه‌مرحله‌ای) — اگه کار نکرد، به‌صورت خودکار فقط متن پست (بدون عکس) فرستاده می‌شه، هیچی گم نمی‌شه.
- **دریافت** عکس/فایل از یه کانال مبدای روبیکا — فعلاً فقط متنِ پیام رو می‌گیره و بازنشر می‌کنه؛ اگه پیام فایل/عکس هم داشته باشه، یه هشدار کوتاه بهش اضافه می‌شه که فایل بازنشر نشده (چون متد رسمی دانلود فایل از روبیکا رو نتونستم کامل تأیید کنم).
- ثبت وبهوک روبیکا (`/rubika-setup`) — اگه خروجیش خطا نشون داد، همون پیام خطا رو برام بفرست تا دقیق‌ترش کنم.

ارسال و دریافت **متن** با روبیکا کاملاً طبق مستندات رسمی پیاده شده و باید بدون مشکل کار کنه.
